# Localización: español y chino simplificado

LIFE DUEL 2.4 incorpora una segunda interfaz completa en **chino simplificado** (`zh-Hans`) sin duplicar el motor de simulación ni alterar una sola partida. El español sigue siendo el idioma de referencia y el estado interno no cambia: semilla, decisiones, IDs, estadísticas y resultados son exactamente los mismos en ambos idiomas.

## Cómo se elige el idioma

- Selector **ES / 中文** en la cabecera, en el menú móvil, en **Ajustes** y dentro de la partida.
- `?lang=zh` o `?lang=es` en la URL fuerza el idioma.
- La preferencia se guarda en `localStorage` (`life-duel.locale.v1`).
- Si no hay preferencia y el navegador está en chino, se abre en chino.
- El documento actualiza `lang="zh-Hans"` y la tipografía china (`PingFang SC`, `Noto Sans SC`) para que el texto se lea con ritmo correcto.

## Arquitectura

| Capa | Archivo | Responsabilidad |
| --- | --- | --- |
| Catálogo | `shared/src/i18n/zh.ts` | Traducciones versionadas. Generado, no se edita a mano. |
| Traducción | `shared/src/i18n/index.ts` | Texto exacto, fechas, cantidades, plantillas narrativas y primera frase de una escena. |
| Textos fuente | `data/i18n/*.json` | Extracción, traducciones automáticas, términos revisados y plantillas. |
| Cliente | `client/src/i18n/LocaleProvider.tsx` | Preferencia, `t()`, traducción de nodos y atributos ya renderizados. |
| Servidor | `server/src/i18n.ts` | Cabecera `X-Locale`, `Content-Language` y localización de respuestas JSON. |
| Scripts | `scripts/extract-i18n.mjs`, `build-zh-catalog.mjs`, `translate-zh-missing.mjs` | Extraer, generar el catálogo y completar huecos. |

### El motor no se traduce

La simulación guarda siempre los textos y datos originales. La localización ocurre **solo en presentación**:

1. El cliente envía `X-Locale: zh` en cada petición.
2. El servidor envuelve `res.json` y recorre los valores textuales con `localizeDeep`.
3. Las claves de protocolo (`id`, `status`, `worldSeed`, `country`, `sex`, `currency`, `optionId`, etc.) nunca se traducen.
4. Los nombres propios (`givenName`, `surname`, `partnerName`) se conservan.
5. Socket.IO transporta el mismo estado neutral; el cliente traduce los textos visibles.

Esto evita dos verdades distintas para la misma partida y permite que un jugador use español y el otro chino en el mismo duelo.

### Plantillas narrativas

Las escenas del motor se construyen con datos variables (ciudad, país, nombre, ocupación, cifras). El catálogo incluye plantillas con huecos:

```text
Origen:  Tuviste fiebre de madrugada en {{x}}. Alguien pasó la noche...
Destino: 您在 {{x}} 清晨发烧。有人在椅子上度过了一夜...
```

El runtime compila cada plantilla a una expresión regular, captura los fragmentos, los traduce si son etiquetas conocidas y los reinserta. También genera automáticamente la **primera frase** de cada escena para los títulos del historial. Las plantillas con placeholders posicionales (`{{1}}`, `{{2}}`) permiten reordenar la frase en chino sin perder el orden lógico.

## Cobertura y calidad

- Más de 5.000 cadenas de interfaz y motor, 130 formas numéricas y unas 180 plantillas narrativas.
- Revisión manual de términos visibles: navegación, estadísticas, economía, vivienda, empresa, países, ciudades principales, meses y estados.
- La traducción automática se usa **una sola vez** para crear el catálogo; no se llama a ningún servicio en tiempo de ejecución y el juego funciona sin red.
- `data/i18n/missing.json` enumera las cadenas que aún no tienen traducción. No se presenta como cobertura total.
- Los nombres propios de lugares menores pueden conservarse en alfabeto latino: es una limitación deliberada y visible, no un texto olvidado.
- Las respuestas de IA (si se configura DeepSeek) se validan y se muestran con reserva local; el modelo nunca modifica estadísticas ni tiradas.

## Flujo para añadir o corregir textos

```bash
# 1. Extraer cadenas y plantillas del código
npm run i18n:extract

# 2. Traducir los huecos (servicio externo solo en desarrollo)
npm run i18n:translate

# 3. Regenerar el catálogo versionado
npm run i18n:build

# 4. Comprobar
npm run typecheck
npm test -- --run
npx playwright test e2e/i18n.spec.ts e2e/i18n-content.spec.ts
```

Los términos que deben revisarse a mano se editan en `data/i18n/zh-overrides.json`; las plantillas narrativas en `data/i18n/zh-templates.json`. Después se ejecuta `i18n:build`. Nunca se edita `shared/src/i18n/zh.ts` directamente: se regenera.

## Limitaciones conocidas

- La calidad de las cadenas automáticas es buena para etiquetas y frases cortas, pero puede sonar literal en narrativa muy específica. Los términos visibles principales están revisados.
- Los topónimos menores y los nombres de personas se mantienen tal cual.
- El texto de Socket.IO no se localiza en el servidor; el traductor del cliente cubre los nodos renderizados y el matcher de plantillas cubre la narrativa del historial.
- Añadir un tercer idioma requiere un catálogo y un conjunto de plantillas nuevos, pero no tocar el motor ni las reglas de puntuación.
